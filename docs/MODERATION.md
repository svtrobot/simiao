# 内容与账号管理

对应设计文档第八章（合规、心理安全）。入口是 `/admin`（需要 `ADMIN_TOKEN`）的「检举与内容」「账号」两块。

## 原则：后台只看公开的东西

| 内容 | 谁看得到 | 后台 |
|---|---|---|
| 祈愿牌 | 殿里所有人 | 可查看、下架、恢复 |
| 灯墙上的名字与心愿 | 殿里所有人（名字已遮：陈○美） | 可查看（同样是遮过的名字）、下架、恢复 |
| 带自伤念头的祈愿牌、灯上心愿 | 只有本人（CLAUDE.md 规则 4） | **看不到**，也不能被检举、下架或“恢复”成公开 |
| 祖先堂：灵位、照片、寄语 | 只有家人 | **看不到**。账号页只显示“家堂 N 个” |
| 生日、心情、推送订阅 | 只有本人 | 看不到 |

这几条都有测试（`test/moderation.test.js`）。

## 检举

- 祈愿墙上每块别人的牌子有「检举」，点开是三个预设理由：广告、不当、其他。**没有自由文字**（和“只有预设致意”同一个考虑）。
- 每人对同一块牌子只算一次；每个账号一天最多 10 次；不能检举自己的；被禁言的账号不能检举。
- **三个不同的人**检举同一块 → 先从墙上收起（`held`），等后台看。后台按「保留」后回到墙上，之后再有人检举也不会自动收起。
- 灯墙的检举接口已有（`kind: "lamp"`），客户端入口还没做——灯上的名字本来就遮着，心愿不超过 40 字且过了禁语。

## 下架与恢复

- 祈愿牌下架：从墙上消失，不能再被随喜。
- 灯下架：**灯照样亮着**（不熄别人的灯），只是墙上不显示名字与心愿；祈福卡上的心愿也不显示。
- 下架要填原因，记在操作记录里。已下架的在「已收起 / 已下架」里可以恢复。

## 禁言

- 被禁言的账号：不能再挂祈愿牌；点灯只能为自己点、灯上不能写字；不能检举。
- **不受影响**：进殿、静坐、上香、功德、祖先堂、已买的道具。
- 禁言时可以选择同时把这个账号目前公开的内容全部下架。
- 可以随时解除。

## 操作记录

下架、保留、禁言、解除禁言都会记一笔（时间、对象、原因），后台显示最近 50 笔。后台目前只有一把共用令牌，所以记录里没有“是谁做的”。

## 接口

- 用户：`POST /api/report`（`{ kind, id, reason }`）
- 后台：`GET /api/admin/content?kind=&filter=&q=`、`POST /api/admin/content/:kind/:id/hide|restore`、`GET /api/admin/users?q=`、`GET /api/admin/users/:id`、`POST /api/admin/users/:id/mute|unmute`、`GET /api/admin/modlog`
- 代码：`server/domain/moderation.js`

## 还没有

- 删除账号 / 导出个人资料（用户提出时目前只能手动处理）。
- 封禁（完全不能进入）——现在只有禁言。
- 每位管理员各自的账号与权限。
- 机构（庙主）自己管理自己寺院内容的后台。
- 列表是扫描全部祈愿牌 / 账号，内测规模没问题；用户多了要和「大集合按需载入」一起改。
