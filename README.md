# 云上寺 · Cloud Sanctuary

手机浏览器打开即进入、无需下载的多人 3D 心灵空间。
安静地坐一会儿，上一炷香，看见身边也有人在静坐——一起，但不打扰。

本仓库是设计规划中 **P0 原型** 的实现：一座中式大殿、上香 / 求签掷筊 / 木鱼 / 念珠 / 静坐 / 祈愿牌、每房间 100 人同殿、招牌化身「泥生」，以及为后续 SaaS 开庙和大陆景点预留的底座（场景包、地区合规模式、开庙审核）。

> 首发市场：台湾与海外华人（界面默认繁体）。大陆部署用 `REGION=cn`，自动切换为文化参访模式（见 [docs/COMPLIANCE.md](docs/COMPLIANCE.md)）。

## 快速开始

需要 Node.js 20 以上，**没有任何 npm 依赖**。

```bash
npm start                 # http://localhost:8787
ADMIN_TOKEN=换成长随机串 npm start   # 同时开启平台后台 /admin
npm test                  # 71 项服务端测试（5 项需要 PostgreSQL / Redis，未设置时跳过）（房间、分线、功德、签、点灯、黄历、禅房与抄经、祖先堂与烧纸、账号、提醒、场景语汇、合规、审核）
npm run loadtest          # 压测：默认 200 人、20 秒
npm run vendor:three      # 把 three.js 下载到 client/vendor（自托管，大陆必须）
docker compose up -d --build   # 容器方式（先把 .env.example 复制为 .env）
```

上线到服务器：把仓库放到服务器，`.env` 里填 `ADMIN_TOKEN` 和 `DOMAIN`，执行 `sh deploy/server-setup.sh`。它会按需安装 Docker，再用 `docker-compose.prod.yml` 把应用和 Caddy 一起拉起，Caddy 自动配置 HTTPS（摇手机求签与 WSS 都需要 HTTPS）。如果服务器上已经有 Caddy，可改用 `deploy/Caddyfile`。

打开首页 → 「进入山门」→ 选心情 → 进殿。多开几个浏览器窗口即可看到彼此。

| 地址 | 说明 |
|---|---|
| `/` 或 `/t/main` | 官方主寺 |
| `/t/<代号>` | 审核通过的分寺 |
| `/c/<卡号>` | 祈福卡：别人为你点的灯，进门后直接走到灯墙上那盏灯前 |
| `/admin` | 平台后台：开庙审核、场景包注册表、在线状态 |
| `?q=low\|med\|high` | 强制画质档位 |
| `?hour=20` | 预览某个时刻的天色（默认跟随本地时间） |

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 端口 |
| `REGION` | `tw` | `tw` / `overseas` / `cn`，决定时区、语言、仪式是否开放、能否自助开庙、心理援助热线 |
| `DATA_DIR` | `./data` | 数据目录（P0 用 JSON 文件，P1 换 PostgreSQL） |
| `ADMIN_TOKEN` | 空 | 平台后台令牌；为空则后台关闭 |
| `ROOM_CAPACITY` | `100` | 每个房间（分线）上限 |
| `TICK_HZ` | `10` | 房间同步频率 |

## 目录

```
server/            Node 服务（零依赖）
  realtime/        WebSocket（RFC 6455 自实现）、房间、分线
  domain/          功德与修行、求签掷筊、香火与愿望墙、开庙、场景注册表、合规
  store/           JSON 文档存储（接口与将来的 PostgreSQL 仓储一致）
client/            浏览器端（ES Modules + three.js，无构建步骤）
  src/world/       场景包加载、程序化大殿、天色季节、烟与落花
  src/avatar/      泥生：形体、五阶段釉色着色器、IK 动作
admin/             平台后台
scenes/            场景包（manifest.json）；_template 为新景点交付模板
content/           签诗等内容数据
docs/              架构、协议、场景包、合规、路线图
test/              node:test 测试
tools/             压测、three.js 自托管
```

## 已实现

- **同殿共修**：每房间 100 人，满员自动开新房间（用户无感），全寺在线与香火每 5 秒聚合；少于 30 人时用半透明「影子同修」补位并明确标注。
- **只有预设致意，没有文字聊天**：合掌 / 顶礼 / 随喜 / 愿你安好；被致意时泥生会转头并自动回一个问讯。
- **仪式**：上香（长按点燃 → 举香齐眉三拜 → 插入香炉，烟随香燃）、求签（摇手机或按钮 → 落签 → 掷筊，圣筊才揭示，三次后依古例取签）、木鱼、念珠 108、静坐（呼吸引导逐渐变慢，心灯越坐越亮）、祈愿牌与随喜、点灯（光明灯 / 药师灯 / 长明灯，供于灯墙；为他人点灯生成祈福卡链接）、黄历（农历干支、节气节日、宜忌、黄道吉时、流年太岁、每日一句；填生日后看生肖与本命佛）。
- **功德买不到**：全部在服务端计算并限速、按地区本地日封顶；付费道具不加功德（P0 尚未接支付）。
- **泥生**：素坯 → 素烧 → 施釉 → 窑变 → 金缮五阶段；窑变颜色由修行习惯决定；久未到访后归来会多一道金缮线；背后有按用户 ID 生成的指纹。全部是着色器参数，没有贴图。
- **心理安全**：愿望里出现自伤念头时不公开悬挂，只给本人温和回应与当地热线。
- **场景扩展底座**：场景包 manifest 校验（性能预算、槽位、地区、合规模式、授权字段），后台可重新载入；glTF 场景包可直接加载。
- **开庙审核**：自称寺 / 庙 / 宫 / 观 / 神社须附登记证，否则只能以「文化空间」开设；大陆区关闭自助开庙。

## 已知限制（P0）

- 场景与人物均为程序化生成，用于验证玩法与性能；写实美术、实地录音按设计文档第十一章另行制作后通过场景包替换。
- 数据存于本机 JSON 文件，单进程。多进程 / 多机需要 P1 的 PostgreSQL + Redis（见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)）。
- 账号：游客即可进入；可用通行密钥或恢复码保存（docs/ACCOUNTS.md）。手机号 / 社交登录、支付、会员在 P1。
- 泥生已改为 GPU 实例化绘制：96 人同殿整帧约 148 draw calls（原 1,694）；还需在中低端真机上确认帧率。
